# Бэкенд команды

Python 3.13, FastAPI + uvicorn, MCP (stdio) для Claude Code, httpx. Базы нет намеренно:
журнал — `data/logs/events.jsonl`, контекст — markdown-файлы, транскрипты — json по файлу
на вызов. Всё читается глазами и grep-ом.

## Команды

| Команда | Что делает |
| --- | --- |
| `./run-dashboard.sh` | API и Swagger на http://localhost:8770 |
| `./run-mcp.sh` | MCP-сервер команды (его запускает сам Claude Code, руками не нужно) |
| `.venv/bin/python -m compileall fleet dashboard` | быстрая проверка синтаксиса (на Windows — `.venv/Scripts/python.exe`) |

Виртуальное окружение — `backend/.venv`, зависимости пинятся точно в `requirements.txt`.
Исполняемые файлы в нём лежат в `bin` на macOS и Linux и в `Scripts` на Windows.

Для Windows те же пусковые файлы лежат рядом с расширением `.cmd` — они нужны для cmd.exe и
PowerShell и ими же регистрируется MCP-сервер. Сами `.sh` каталог окружения ищут, а не
угадывают, поэтому из Git Bash (а им Claude Code выполняет команды на Windows) работают тоже.
Правишь один — правь и пару: разъехавшиеся пусковые файлы находятся уже на новой машине,
когда чинить их некогда.

## Модули

- `fleet/config.py` — типы провайдеров, моделей, ролей и пространств. Значений в коде нет:
  всё, что правит человек, лежит в данных и перечитывается по mtime.
- `fleet/layout.py` — раскладка каталога данных. Единственное место, где зашиты имена
  файлов; остальные модули спрашивают путь у него, а не складывают строки сами. Сам корень
  ищет `config._data_root()`: `FLEET_DATA`, затем `data-path.local` рядом с инструментом,
  затем соседний каталог `AGENT.Dashboard.DATA`. Данные лежат вне репозитория инструмента —
  он чистая обёртка.
- `fleet/paths.py` — пути этой машины: клон репозитория пространства и папка его данных.
  Лежат вне git, потому что на другом устройстве они другие.
- `fleet/client.py` — вызов модели, ретраи, фолбэк, учёт стоимости и запись транскрипта.
- `fleet/providers.py` — заголовки авторизации (bearer / api-key / gigachat / anthropic)
  и проверка связи.
- `fleet/anthropic.py` — диалект Claude: адрес `/v1/messages`, ключ в `x-api-key`,
  системный промпт отдельным полем, ответ блоками. Температуры и `budget_tokens`
  у моделей 4.6+ в API больше нет — не отправляем.
- `fleet/agents.py` — делегирование: ask, batch, council, look, research, intake, правила из репы.
- `fleet/team.py` — состав команды пространства (`Composition`: роли, отделы, карточки
  регламентов, назначения) и общий реестр провайдеров и моделей. Любое чтение состава
  называет пространство: одно имя роли в двух проектах — это два разных агента.
- `fleet/charter.py` — регламенты: отделы и уставы. Текст лежит в
  `projects/<проект>/charters/*.md`, карточки — в его `team.json`; подходящие документы
  уходят в системный промпт агента ПЕРЕД его ролевым.
- `fleet/context.py` — контекст-банк (`projects/<проект>/context/`); `_core.md`,
  `_rules.md` и выжимка летописи `CONTEXT.md` всегда в префиксе промпта.
- `fleet/migrate.py` — однократный перенос данных из прежней плоской раскладки.
  Дёргается при запуске дашборда и MCP-сервера: клон данных приезжает на новую машину
  как есть, и помнить про скрипт миграции человек не обязан.
- `fleet/journal.py` — летопись пространства: ARCHITECTURE, HISTORY, TASKS, BUGS и
  выжимка CONTEXT. Память команды между сессиями, наружу торчит `fleet_journal`.
  Запись в летопись оформляет летописец (дешёвая модель), а доски задач и багов
  правятся без вызова модели: пункт доски — одна строка, платить за её
  оформление нечем.
- `fleet/usage.py` — свод расхода по дням: `projects/<проект>/stats.json` и общий
  `stats.json`. Коммитится вместе с памятью, поэтому история расхода переживает переезд;
  журнал вызовов остаётся рантаймом. Пишется прямо из `log.emit`, чтобы вызов не мог
  попасть в журнал и не попасть в свод.
- `fleet/stats.py`, `fleet/claudecode.py` — статистика команды (считается по своду) и
  расход самого Claude Code (по журналам его сессий).
- `dashboard/app.py` — HTTP API, `dashboard/schemas.py` — схемы ответов (из них типы фронта).

## Правила

- **Стиль:** 4 пробела, snake_case, docstring у каждого модуля и у неочевидных функций,
  аннотации типов обязательны. Строки до ~100 символов.
- **Порядок в промпте не трогать:** неизменный блок контекста идёт строго первым. У DeepSeek
  попадание в префиксный кэш дешевле промаха примерно в 50 раз.
- **Секреты не логировать и не возвращать наружу.** Наружу отдаётся признак «ключ задан».
- **Ошибки провайдера показывать как есть** — код HTTP и его текст. «Что-то пошло не так»
  бесполезно тому, кто настраивает подключение.
- **Новое поле ответа заводится в `schemas.py`**, иначе оно не доедет до фронта.
- **Пути к файлам данных берутся из `fleet/layout.py`.** Склеивать их в модуле нельзя:
  раскладка меняется, и вторая правда о том, где лежит `team.json`, однажды разойдётся.
- **Цифры расхода — только из свода (`fleet.usage`).** Считать их обходом журнала заново
  значит завести вторую правду: журнал на новой машине пуст, а свод приезжает с данными.
- Длинные выхлопы агентов уходят в `data/out/*.md`, в контекст Claude возвращается выжимка.

## Пространства привязаны к каталогам

У пространства есть `repo` — путь к клону репозитория. В данных его нет: он свой на
каждой машине и лежит в `data/paths.local.json` (`fleet/paths.py`), а в `config.Workspace`
подставляется при чтении. Он не украшение и не подсказка для импорта правил:

- по нему `config.workspace_of(путь)` узнаёт пространство по рабочему каталогу,
  включая работу из подпапок (`backend/`, `src/widgets/...`);
- MCP-инструменты берут пространство из каталога, если его не назвали явно, и
  **не дают писать заметки в чужое пространство** из чужого каталога (`server._space`);
- расход Claude Code раскладывается по проектам по этому же пути, а не по имени
  папки — иначе один проект рассыпается на `src`, `ui`, `backend` и десяток слайсов.

Рабочий каталог берётся из `FLEET_CWD`: пусковой файл кладёт туда `$PWD` (в `.cmd` — `%CD%`)
до перехода в свою папку, потому что после `cd` `os.getcwd()` указывает на backend,
а не на проект.
Название пространства — алиас, его можно менять; опознаётся пространство по пути.

Второй локальный путь — папка данных пространства. Пустая означает `data/projects/<id>`
в общем клоне; заполненная уводит контекст проекта в выбранное человеком место. Оба пути
пишет дашборд (вкладка «Пространства», выбор папки в модалке), руками их править не надо.
