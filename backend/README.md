# Бэкенд AGENT.Dashboard

MCP-сервер команды для Claude Code и HTTP API для интерфейса. Python 3.13, FastAPI, httpx.
Базы данных нет намеренно: журнал — `data/logs/events.jsonl`, память — markdown-файлы,
транскрипты вызовов — json по файлу на вызов. Всё читается глазами и grep-ом.

## Запуск

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
./run-dashboard.sh        # http://localhost:8770 — API, Swagger на /docs, ReDoc на /redoc
```

MCP-сервер (`./run-mcp.sh`) запускает сам Claude Code, руками его дёргать не нужно:

```bash
claude mcp add fleet -s user -- /путь/к/AGENT.Dashboard/backend/run-mcp.sh
```

Ключи берутся из `data/secrets.json` (их задают в интерфейсе), при отсутствии — из окружения;
`run-mcp.sh` дополнительно подхватывает `GLM_API_KEY` и `DEEPSEEK_API_KEY` из `~/.zshrc`,
чтобы не держать секреты в конфиге Claude.

## Провайдеры

Провайдер описывается адресом и способом авторизации; и то, и другое правится в интерфейсе.

| Способ | Заголовок | Кому |
| --- | --- | --- |
| `bearer` | `Authorization: Bearer <ключ>` | GLM, DeepSeek, OpenAI-совместимые, OpenRouter |
| `api-key` | `Authorization: Api-Key <ключ>` | Yandex Cloud |
| `gigachat` | обмен ключа на access_token, затем Bearer | GigaChat (Сбер) |

У GigaChat выключается проверка TLS: его цепочка подписана НУЦ Минцифры, которого нет в
системном хранилище. Поле `thinking` понимают только GLM и DeepSeek — прочим его слать нельзя,
для этого у провайдера есть отдельный флаг.

## Что выяснено про провайдеров живыми запросами

Это не догадки, а результат проверки — они определяют конфигурацию:

- **GLM отвечает только через coding-эндпоинт** `api.z.ai/api/coding/paas/v4`. Обычный
  pay-per-token `/paas/v4` даёт `1113: Insufficient balance`.
- **Подписка ≠ каталог.** Реально доступны `glm-5.3`, `glm-5.3-flash`, `glm-4.6v`; остальные
  имена молча подменяются, клиент логирует факт подмены.
- **Остаток подписки z.ai через API не отдаёт** — проверено на `/usage`, `/account/quota`,
  `/user/balance` и заголовках ответа. Баланс отдаёт только DeepSeek.
- **Поиск GLM на Coding Plan не работает**, поэтому поиск свой: DuckDuckGo плюс опциональный
  локальный SearXNG (`docker run -d -p 8888:8080 searxng/searxng`).
- **`max_tokens` ограничивает выход вместе с размышлениями.** У думающей роли лимит уходит
  в раздумья, а ответ приходит пустым. Лечится запасом сверх лимита и авто-повтором.

## Перенос на другую машину

Смысл разделения на два репозитория в том, что переносить почти нечего: инструмент и память
приезжают `git clone`, а руками остаётся только то, что и не должно лежать в git.

**Приезжает само:** составы команд с промптами ролей, отделы и регламенты, контекст и летопись
пространств, реестр провайдеров и моделей, служебные промпты и подсказки.

**Ставится заново** (окружение, а не данные):

```powershell
git clone https://github.com/AlexandraG-code/AGENT.Dashboard.git
cd AGENT.Dashboard
git clone https://github.com/<логин>/AGENT.Dashboard.DATA.git data

py -3.13 -m venv backend\.venv
backend\.venv\Scripts\pip install -r backend\requirements.txt
cd frontend; yarn install; cd ..
```

Виртуальное окружение между машинами не переносится: в нём лежат бинарники под свою ОС.
Версии зависимостей пинятся точно в `requirements.txt`, так что ставится то же самое.

**Заполняется руками — три вещи, и все по одной причине: они про эту машину, а не про проект.**

1. **Ключи провайдеров.** В git их нет даже в приватном репозитории. Задаются в дашборде на
   вкладке «Модели» и ложатся в `data/secrets.json`; можно и переменными окружения
   (`GLM_API_KEY`, `DEEPSEEK_API_KEY`). Проще ввести заново, чем возить файл с ключами.
2. **Пути к клонам репозиториев.** Вкладка «Пространства» → «Каталог репозитория», выбор папки
   в обзоре. Ложатся в `data/paths.local.json` — он не коммитится, потому что на маке это
   `/Users/...`, а на windows `D:\...`. Там же поле «Папка данных проекта», если контекст
   какого-то пространства лежит не в общем клоне.
3. **Регистрация MCP-сервера в Claude Code.** Она хранится в `~/.claude.json` с абсолютным
   путём к пусковому файлу, поэтому задаётся на каждой машине своя:

   ```powershell
   claude mcp add fleet -s user -- C:\путь\к\AGENT.Dashboard\backend\run-mcp.cmd
   ```

Пусковые файлы лежат парами: `run-mcp.sh` и `run-dashboard.sh` для macOS и Linux,
`run-mcp.cmd` и `run-dashboard.cmd` для Windows. Делают они одно и то же, включая главное —
кладут рабочий каталог в `FLEET_CWD` ДО перехода в свою папку, иначе команда решит, что
работа идёт в `backend`, а не в проекте.

Цифры расхода переезжают: они лежат в своде (`data/stats.json` и
`data/projects/<проект>/stats.json`), который коммитится. Свод пополняется на каждом вызове
и отвечает на вопросы «сколько всего потрачено» и «когда работали»; общий файл нужен
затем, что иначе итог пришлось бы собирать обходом всех пространств, включая
несклонированные.

Чего в переносе нет намеренно: журнал вызовов, транскрипты и выхлопы агентов (`data/logs`,
`data/calls`, `data/out`). Это рантайм: живая лента и разбор конкретного вызова нужны на
той машине, где работа идёт, а история расхода уже сохранена в своде.
