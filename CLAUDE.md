# AGENT.Dashboard

Свой «отдел разработки» из дешёвых моделей под управлением Claude Code: MCP-сервер команды,
API и веб-интерфейс со статистикой расходов.

> Язык проекта — русский. Комментарии, сообщения коммитов и тексты интерфейса — по-русски.

## Раскладка

| Каталог | Что там |
| --- | --- |
| `backend/` | MCP-сервер команды и FastAPI. Свои правила — `backend/CLAUDE.md` |
| `frontend/` | интерфейс на Next.js. Свои правила — `frontend/CLAUDE.md` |
| рядом | память команды: пространства с их составом, контекстом и расходом. Отдельный приватный репозиторий `AGENT.Dashboard.DATA`, склонированный соседней папкой |

Правила ниже общие для обеих частей; частности — в `CLAUDE.md` соответствующей папки.

## Общие правила

- **Никакого подавления ошибок:** ни `# type: ignore`, ни `@ts-ignore`, ни `any`, ни
  `eslint-disable`. Чинится причина, а не симптом.
- **Комментарий объясняет «почему», а не «что».** Строчка `# увеличиваем счётчик` — мусор;
  строчка про то, что префикс промпта обязан быть побайтово одинаковым ради кэша, — нет.
- **Не выдумывать данные.** Если провайдер не отдаёт остаток лимита, в интерфейсе так и
  написано, а не подставлено правдоподобное число. То же про цены и статистику.
- **Ключи и контекст рабочих проектов в git не уезжают.** Ключи — `data/secrets.json`,
  контекст — приватный репозиторий `data/`. Публичный репозиторий содержит только инструмент.
- **Схема данных живёт в одном месте.** Ответы API описаны в `backend/dashboard/schemas.py`;
  из них строятся и Swagger на `/docs`, и типы фронта. Руками типы ответов не пишутся.
- **Документация — блоком над сущностью, а не построчно.** У компонента — JSDoc с `@param`
  на каждое свойство; у модуля и неочевидной функции — docstring. Построчные комментарии
  внутри интерфейсов и датаклассов не пишем.
- **Файл — про одну вещь.** Свалка из десятка функций над основным содержимым разносится
  по сегментам (`model/`, `lib/` во фронте; отдельный модуль в бэкенде), даже если функции мелкие.
- **Не писать руками то, что есть в библиотеке.** Во фронте это antd 5: кнопки, поля, таблицы,
  вкладки, модалки берутся оттуда. Стили — только SCSS-модули, инлайн-стилей нет.
- Коммиты — с префиксом в квадратных скобках: `[feat]`, `[fix]`, `[refactor]`, `[docs]`.

## Что нужно знать о команде

- **Команда у каждого пространства своя.** Роли, их промпты, отделы, регламенты и
  назначения лежат в `data/projects/<проект>/team.json` и правятся в дашборде; в коде
  нет ни одной роли. Общими остаются только провайдеры и модели (`data/registry.json`):
  это свойство аккаунта, а не проекта.
- **Всё про проект — в его папке:** `data/projects/<проект>/` (состав, контекст,
  летопись, регламенты, лента, материалы). Папку можно скопировать, и проект приедет
  целиком. Имена файлов внутри знает только `backend/fleet/layout.py`.
- **Путей в git нет.** Клон репозитория и папка данных пространства свои на каждой
  машине и живут в `data/paths.local.json` (вне git), а пишет их дашборд.
- **Код пишут агенты, а не главный архитектор.** Главный ставит задачу и принимает
  результат; ответ агента раскладывает по файлам `fleet/apply.py` — только внутри
  каталога пространства и только по разрешённым расширениям. Наружу пути не
  выпускаются: они приходят из текста, сгенерированного моделью. Ничего не
  удаляется — файл можно перезаписать, но не стереть. Главный видит отчёт
  «создан/обновлён файл, столько-то строк», а не сам код: его токены дороже всех.
- **Память между сессиями — летопись пространства**, а не чей-то контекст:
  `data/projects/<проект>/context/` — ARCHITECTURE, HISTORY, TASKS, BUGS и короткая
  выжимка CONTEXT.md. Сессия начинается с `fleet_journal(action="brief")` и заканчивается
  `action="entry"`; выжимка уходит в промпт каждого агента, так что представление о
  проекте одинаковое у всех. Оркестратором может быть любая модель — порядок работы
  с памятью она получает из инструкций MCP-сервера (`fleet/server.py`), а не из
  договорённостей в чате.
- **Задачи берутся с доски, а не выводятся из истории.** `TASKS.md` и `BUGS.md`
  пространства ведут человек в дашборде (вкладка «Контекст») и оркестратор —
  `fleet_journal(action="task"|"doing"|"done"|"bug")`. Это дёшево: пункт доски
  пишется без вызова модели. Порядок такой: понял, что делать, — положил на доску,
  потом раздал агентам. Чего на доске нет, то умрёт вместе с сессией.
- В интернет агенты ходят только через свои инструменты.
- Обсуждение агентов между собой идёт внутри процесса (`council`), наружу отдаются позиции
  и разногласия. Свободный чат агентов жжёт токены и уплывает от задачи.
