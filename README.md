# AGENT.Dashboard

Сеть агентов на нескольких провайдерах: Claude Opus как главный архитектор, GLM и DeepSeek как команда.
Управляется из Claude Code через MCP, наблюдается через локальный дашборд.

## Как это устроено

```
Вы (технический директор)
      │
Claude Opus — главный архитектор: файлы, git, финальное ревью, решения
      │  MCP-сервер fleet (stdio, локально)
      ├── consultant   glm-5.3              второе мнение по архитектуре
      ├── opponent     deepseek-v4-flash    оппонент в совете (другая семья моделей)
      ├── senior       deepseek-v4-pro      сложная логика, рефакторинг, интеграции
      ├── junior ×N    glm-5.3-flash        простой код, рутина (параллельно до 50)
      ├── vision       glm-4.6v             скриншоты, макеты, схемы → текст
      ├── analyst      glm-5.3-flash        логи, метрики, JSON, аномалии
      └── condenser    glm-5.3-flash        сжатие страниц и выдачи поиска
      │
контекст-банк data/context/<проект>/   +   журнал data/logs/events.jsonl → дашборд
```

**Топология — звезда, а не общий чат.** Свободная переписка агентов между собой жжёт токены
и уплывает от задачи. Обсуждение выполняется внутри процесса (`fleet_council`), а наружу
отдаются только позиции сторон — решение принимает главный архитектор.

**Агенты не пишут в файлы.** Они возвращают код текстом, применяет его Claude после проверки.
Так каждое изменение проходит ревью и видно в диффе.

## Экономика

GLM — подписка Coding Plan: маржинальная стоимость вызова **ноль**, ограничение только
по параллелизму и квоте окна. DeepSeek — оплата по токенам. Отсюда главное правило:
**всё, что GLM делает приемлемо, идёт в GLM; деньги DeepSeek покупают только то, чего GLM не может.**

| Модель | Вход / 1M | Кэш-хит | Выход / 1M |
| --- | --- | --- | --- |
| `glm-5.3`, `glm-5.3-flash`, `glm-4.6v` | 0 | 0 | 0 |
| `deepseek-v4-flash` | $0.14 | $0.0028 | $0.28 |
| `deepseek-v4-pro` | $0.435 | $0.003625 | $0.87 |

Типовая задача (8k вход, 10k выход): senior ≈ $0.012, оппонент ≈ $0.004, джун — бесплатно.

Три приёма экономии заложены в код:

1. **Префиксный кэш.** У DeepSeek попадание в кэш в 50 раз дешевле промаха, поэтому неизменный
   блок контекста проекта (`_core.md`) всегда идёт первым и побайтово одинаково от вызова к вызову.
   Всё зависящее от задачи подмешивается после него (`fleet/context.py`).
2. **Размышления по делу.** DeepSeek V4 думает по умолчанию, а размышления биллятся как выход.
   У джунов думанье выключено явно, у senior и оппонента включено — там оно и есть предмет покупки.
3. **Объёмное — в файлы.** Ответы длиннее 6000 символов складываются в `data/out/`, в контекст
   Claude уходит путь и выжимка (`fleet/server.py`).

## Что выяснено про провайдеров живыми запросами

Это не догадки, а результат проверки — они определяют конфигурацию:

- **GLM отвечает только через coding-эндпоинт** `api.z.ai/api/coding/paas/v4`. Обычный
  pay-per-token `/paas/v4` даёт `1113: Insufficient balance`.
- **Подписка ≠ каталог.** Реально доступны три модели: `glm-5.3`, `glm-5.3-flash`, `glm-4.6v`.
  Остальные имена молча подменяются (`glm-4.7` → `glm-5.3-flash`, `glm-5.2` → `glm-5.3`),
  а `glm-5v-turbo` отвечает `1311: не входит в подписку`. Клиент логирует факт подмены.
- **Поиск GLM на Coding Plan не работает.** Инструмент `web_search` игнорируется, `Search-Prime`
  и `Web-Reader` требуют пополнения баланса. Поэтому поиск свой: DuckDuckGo (POST на `/html/`
  с Referer — GET отдаёт антибот-заглушку) плюс опциональный локальный SearXNG.
- **`max_tokens` ограничивает выход целиком, вместе с размышлениями.** У думающей роли лимит
  уходит в раздумья, а ответ приходит пустым. Лечится запасом сверх лимита ответа
  и авто-повтором с утроенным запасом (`fleet/client.py`).

## Установка

```bash
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
```

Ключи `GLM_API_KEY` и `DEEPSEEK_API_KEY` берутся из окружения; `run-mcp.sh` при их отсутствии
подхватывает их из `~/.zshrc`, чтобы не хранить секреты в конфиге Claude.

Регистрация в Claude Code:

```bash
claude mcp add fleet -s user -- /путь/к/AGENT.Dashboard/run-mcp.sh
```

Дашборд:

```bash
./run-dashboard.sh     # http://localhost:8770
```

Лучший поиск (необязательно): `docker run -d -p 8888:8080 searxng/searxng`.

## Инструменты MCP

| Инструмент | Назначение |
| --- | --- |
| `fleet_ask` | поручить задачу одной роли |
| `fleet_council` | совет: консультант предлагает, оппонент атакует |
| `fleet_batch` | пачка мелких задач параллельно на джунах |
| `fleet_vision` | описать картинку (скриншот, макет, схема) |
| `fleet_research` | найти в сети, прочитать источники, свести ответ |
| `fleet_read` | прочитать страницу по ссылке и сжать до фактов |
| `fleet_context` | контекст-банк проекта: list / get / search / write / append |
| `fleet_status` | расходы, остаток на счёте, роли, статистика |

## Дашборд

- **Лента** — живая хроника вызовов: роль, модель, задача, токены, цена.
- **Запуск** — отправить задачу любой роли или собрать совет прямо из интерфейса.
- **Роли и промпты** — редактор системных промптов. MCP-сервер перечитывает файл по mtime,
  перезапуск не нужен.
- **Контекст проектов** — редактор заметок контекст-банка.

## Проекты

Одна команда, отдельный контекст на каждый проект: `biqube`, `shaks-site`, `shaks-daylik`,
`shaks-llmframework`. Роли и промпты общие, у каждого вызова параметр `project`.

Контекст-банк в `data/context/<проект>/` — обычные markdown-файлы. `_core.md` уходит в промпт
каждого агента целиком, поэтому в нём держатся стек, соглашения и цели. Решения по ходу работы
складываются отдельными заметками — они попадают в промпт только когда относятся к задаче.

Каталог `data/` в `.gitignore`: там контекст рабочих проектов, и он не должен уезжать в репозиторий.

## Почему не NotebookLM

У NotebookLM нет публичного API — программно брать оттуда контекст нельзя. Контекст-банк
закрывает ту же задачу: markdown-заметки с поиском по словам, без внешних зависимостей и индекса.
