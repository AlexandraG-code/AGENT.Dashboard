# Интерфейс флота

Next.js 16 (App Router) + React 19 + TypeScript strict. UI-кит — **antd 5**, стили —
**только SCSS-модули**. Архитектура — Feature-Sliced Design (FSD 2.0), границы проверяет steiger.

## Команды

| Команда | Что делает |
| --- | --- |
| `yarn dev` | http://localhost:3000, `/api/*` проксируется на бэкенд (`FLEET_API`) |
| `yarn build` | сборка с проверкой типов |
| `yarn generateApi` | типы из `/openapi.json` бэкенда (бэкенд должен быть запущен) |
| `yarn lint` / `yarn lint:fsd` / `yarn format` | ESLint, границы FSD, Prettier |

Перед коммитом зелёными должны быть все три: `yarn lint`, `yarn lint:fsd`, `yarn build`.

## Слои и сегменты

`app` → `widgets` → `shared`. Слоя `pages` нет: его роль играют маршруты App Router
в `src/app` — они тонкие и только собирают виджеты.

Внутри слайса сегменты обязательны и делят код по назначению:

- `ui/` — только разметка и обработчики. Ни запросов, ни вычислений.
- `model/` — состояние, хуки, запросы к API, сборка данных для этого слайса.
- `lib/` — чистые функции этого слайса (форматирование, преобразования).
- `index.ts` — публичный API слайса; наружу отдаётся только то, что там перечислено.

**Виджеты не импортируют друг друга.** Нужен общий блок — композиция поднимается в `app`,
общие данные берутся хуком из `shared/model`.

## Правила, которые легко нарушить

- **Никаких хелперов сверху файла компонента.** Функция, объявленная над компонентом, —
  это код, которому место в `model/` (если он про состояние и данные) или в `lib/`
  (если он чистый). В файле компонента остаётся компонент. Файл с десятком функций
  разносится, даже если каждая маленькая: такой файл нечитаем.
- **Стили — только SCSS-модули** `Component.module.scss`, классы через `clsx`.
  Инлайн-стили запрещены. Единственное исключение — передача динамической величины
  CSS-переменной (`style={{ '--bar-width': '42%' }}`), потому что иначе её нечем прокинуть;
  само оформление всё равно живёт в модуле.
- **Не верстать руками то, что есть в antd.** Кнопка — `Button`, выпадающий список — `Select`,
  поле — `Input`/`InputNumber`, переключатель — `Switch`, вкладки — `Tabs`, таблица — `Table`,
  модалка — `Modal`. Свои компоненты пишутся только там, где antd нечего предложить
  (например, стеклянная карточка или полосы графика), и живут в `shared/ui`.
- **Документация — JSDoc над компонентом**, с `@param` на каждое свойство. Построчные
  комментарии внутри `interface` не пишем: описание свойств лежит в блоке над компонентом.
- Компоненты функциональные, без `React.FC`; пропсы — `interface IXxx`; `...props` спредом.
- **Типы ответов API не пишутся руками.** `src/shared/api/schema.ts` генерируется из
  OpenAPI бэкенда, человеческие имена ему даёт `types.ts`. Новое поле — сначала в схему бэкенда.
- Никаких `any` и `@ts-ignore`; необязательные поля обрабатываются явно (`??`).
- **setState синхронно в теле `useEffect` запрещён** (`react-hooks/set-state-in-effect`):
  состояние либо инициализируется из пропсов, либо сбрасывается через `key` на компоненте.
- **Доступность не опция:** видимый focus, `label` связан с полем, кликабельное — это `Button`,
  контраст текста не ниже 4.5:1, размеры в rem. В шапке есть панель «Вид» (кегль, шрифт,
  насыщенность, контраст, фон) — она нужна людям со слабым зрением, не ломать её.
- **Палитра серий на графиках** — `src/shared/config/palette.ts`, порядок фиксирован и проверен
  валидатором (контраст, дальтонизм, полоса светлоты). Порядок не менять.

## Как писать компонент

```tsx
/**
 * Карточка агента: настройки модели и системный промпт.
 *
 * @param agent — выбранный агент; null означает форму создания нового
 * @param models — доступные модели для выпадающего списка
 * @param onSaved — вызывается после успешного сохранения
 */
export function AgentCard({ agent, models, onSaved }: IAgentCardProps) { … }
```

Запросы и состояние формы — в хуке из `model/` этого же слайса (`useAgentForm`), в `ui/`
остаётся разметка на antd и классы из `.module.scss`.
